# 演示视频讲稿（5 分钟）

这是一份**可以直接念**的稿子。每个镜头分三块：

- **画面**：镜头对着哪儿
- **操作**：你手上做什么（念稿时不用管这行）
- **讲稿**：口的原文，按句号停顿即可

正文 **1057 字**，按每分钟 230 字念约 4 分 36 秒，加上点击和停顿正好 5 分钟。
念快了会显得赶，念慢到 200 字/分就是 5:30——**按稿子念，不要临场加词**。

## 镜头 4 ｜ 1:44 – 3:02 ｜ 核心：拦得住，还能自己修

**画面**：执行中心页。
**操作**：闸门卡片右侧「故障注入」选 **语义型 · 金额提前舍入** → 点「重新运行全链路」→ 签核 → 等闸门变红再变绿。

**讲稿**（269 字）

> 接下来是核心。
>
> 我把故障注入切成"语义型"：金额先四舍五入两位，再做零值判断和返利计算。业务上完全说得通，代码也很干净。
>
> 重新跑。
>
> 看结论：编译通过，契约测试通过，人工挑的五条用例，零处差异。
>
> 但算法生成的四十一条用例，发现了二十四处分歧——金额 0.001 的时候，存量返回 0.00，这个实现抛了"金额非法"。
>
> 差别只有一句话：判零用原始金额，还是舍入后的金额。
>
> 这就是静默破坏：编译器看不见，单测看不见，人也容易看漏。
>
> 这一行是用例生成：九十种组合压到四十一例，两两覆盖仍是百分之百。人工用例覆盖想得到的场景，缺陷长在想不到的边界上。
>
> 然后它自己修了：二十四条失败用例回灌给模型，重新生成，复检零差异。
>
> 返工一次，是它自己返的。

## 镜头 5 ｜ 3:02 – 3:37 ｜ 改了什么

**画面**：编辑器里的 diff（Alt+Tab 切过去）。
**操作**：依次指三处。准备命令：

```bash
code --diff hub/sample-project/legacy/src/com/demo/settle/LegacySettleService.java hub/sample-project/modern/src/com/demo/settle/ModernSettleService.java
```

没有 VS Code 就用编辑器并排打开；再没有就把这 35 秒让给镜头 4，直接跳过。

**讲稿**（135 字）

> 这是同一次迁移的前后对比。
>
> 第一处，@TxRequired 两边都在——闸门强制保留的，丢了就被拦。
>
> 第二处，double 换成 BigDecimal，定点数，两位、四舍五入。
>
> 第三处，DAO 从 double 重载换成 String 重载；两种重载走同一个格式化函数，所以 SQL 轨迹必须逐字一致——这正是双跑差分在比的东西。

## 镜头 6 ｜ 3:37 – 4:19 ｜ 效率怎么算的

**画面**：点顶部「总览」，滚到「效率证明」。
**操作**：鼠标依次指 A 列、B 列、差值列，最后指徽标上的「测于 …」。

**讲稿**（170 字）

> 效率这块做了同模块对照。
>
> A 臂是基线：同一个模型、同样两次机会，只给编译报错。它第一次生成的代码，编译器直接报"double 无法转 BigDecimal"——模型臆造了接口。
>
> B 臂是平台：给真实接口面，加五项闸门，失败自动回边。

> 差距不在能不能做对，在几次做对：0% 对 100%。
>
> 一条硬规矩：两臂必须同源，否则这张表直接变红写"不可配对"，不给好看的假数字。
>
> 也说清边界：这证明的是编排，不是人效。

## 录制与剪辑提示

**念稿**

- 每个句号停半拍，段落之间停一拍。技术名词（TxRequired、BigDecimal、DAO）念慢一点。
- 镜头 4 是重点，语速比前面再慢一档，尤其是"二十四处分歧"这句。

- 不要加背景音乐，评审场景容易听不清。
- 目标 5:00，**不要超过 5:30**。超了优先砍镜头 5 和镜头 8，别砍镜头 4。
